# 生词阅读器

输入今天背的单词（+ 可选主题）→ 生成一篇连贯的英文短文 → 跳到独立的阅读页：**左边英文、右边中文，生词两侧同时标记、可点击查词**。

两个页面：**主界面**（输入 + 右侧历史记录）和**阅读页**（左上角返回）。生成过的短文按时间存进历史，随时点回来重读。

数据全部在本机；只有「生成」这一步会把单词和主题发给你选定的那家模型。

## 两家供应商，各填各的 Key

| 供应商 | 端点 | 可选模型 |
| --- | --- | --- |
| 阿里云百炼 · 千问 | `dashscope.aliyuncs.com/compatible-mode/v1` | qwen-plus（默认）/ turbo / max / flash |
| DeepSeek | `api.deepseek.com` | deepseek-chat（默认）/ deepseek-reasoner |

- 设置面板顶部切供应商，**两家的 Key 分开保存，互不影响**；按钮上有绿点 = 该家已填 Key
- 已填过的 Key 以脱敏形式显示（`sk-ws-…h6dc`），不改动就保持原样；要换就「清除」再贴新的
- 主界面底部一行小字写明当前用的是哪家哪个模型，点「切换供应商」直达设置
- 两家都是 OpenAI 兼容接口，服务端对 JSON 模式做了兼容：若某模型不支持 `response_format`，会自动退回普通模式重试（`deepseek-reasoner` 直接不走 JSON 模式）
- 注意：`deepseek-reasoner` 是推理模型，会先想再写，一篇文章可能要一两分钟

## 启动

需要 Node.js 18 以上（[nodejs.org](https://nodejs.org)，装 LTS 版），**不需要 `npm install`，没有第三方依赖**。

```bash
node server.js      # 或 npm start
```

Windows 双击 `启动.bat`，macOS / Linux 用 `./start.sh`；浏览器会自动打开 http://localhost:5173，关闭窗口即停。

首次运行会自动从 `config.example.json` 生成一份空的 `config.json`，Key 到页面右上角 ⚙ 里填（也可以直接改 `config.json`）。

## 用法

1. 主界面单词框：`endurance, resilience, orbit`（逗号 / 空格 / 换行 / 中文逗号都能切分，**最多 50 个**）
   - 下方实时显示 `已选词数 / 50`，超出变红并禁止生成；建议更多词时分批读
   - Enter 直接生成，Shift+Enter 换行
2. 主题框（可选）：`太空`
3. 点「生成」→ 十几秒后自动跳到阅读页
4. 阅读页左上角「‹ 返回」回主界面；右上角分段控件切视图；⚙ 换供应商、填 API Key、选模型

## 界面

- **主界面**：左侧输入卡，右侧「历史记录」栏（最多留 30 条，本机 localStorage；点一条直接打开，行尾 `×` 删除，「清空」全部清掉）
- **阅读页**：顶部毛玻璃工具栏（返回 / 标题 / 视图切换），正文左英文右中文逐段对照，鼠标悬停某一段时该段两侧一起提亮
- **视图**：对照（默认，左英右中）/ 英文（自测）/ 译文 / 词表；切换只改一个变量，四种视图都来自同一份数据
- 浏览器返回键与页面内返回按钮一致（用 hash 路由 `#/read`）
- 视觉按 iOS 设计语言：系统字体、分组灰底、白卡大圆角、毛玻璃、`#007AFF` 蓝，跟随系统深浅色

## 点词查词

- 文中被标出的词都带 `data-k`，点一下：弹出该词的中文释义卡，同时**点亮全文（含译文）里该词的所有出现位置**
- 再点一次或按 Esc 取消；滚动页面自动收起释义卡

## 数据结构

```js
// config.json
{
  "provider": "qwen",                                   // 当前启用哪家
  "qwen":     { "apiKey": "sk-…", "model": "qwen-plus" },
  "deepseek": { "apiKey": "sk-…", "model": "deepseek-chat" }
}
```

```js
// 服务端返回
{
  words: ['endurance', 'resilience', 'orbit'],
  paras: [{ en: '... each [[3|orbit]] every 90 minutes ...',
            zh: '... 每90分钟完成一次[[3|轨道]] ...' }, ...],
  dict:  [{ i: 1, word: 'endurance', zh: '耐力' }, ...],
  coverage, wordCount, attempts
}
```

`[[序号|文中形态]]`：序号即目标词编号，`|` 后是实际出现的形态（屈折变化也如实标）。英文、中文用同一个序号，所以点英文词能点亮中文里对应的译法。服务端会把标记打平成纯文本用于覆盖率校验；前端若发现某段没有标记，还有按词形变形兜底的染色逻辑。

`paras` 的切分：模型给的段落如果左右数量不一致（常见），会退回**按句子切成等份**——英文按 `.!?` 断句、中文按 `。！？；` 断句，取两边句子数的较小值分成 2~8 组，保证左英右中逐段对得上（否则长段落会让两栏错位）。

服务端还有一道 **`ensureMarks()`**：模型经常"用了词但忘了打标记"（实测 30 词里只有 27 个词的英文出现了标记），这时按词形变形在未被标记的文本片段里补上 `[[序号|form]]`，确保每个生词在文中都是可点的 token（中文侧用词条同样的思路补）。

## 保证生词一定出现

- **输入上限 50 词**：输入框实时显示 `已选 / 50`，超出变红且禁止生成
- **长度随词数走**：10 词以内 200~300 词；词越多文章越长（50 词约 600~750 词），避免塞不下还不通顺
- **模型自校验**：提示词要求模型逐个核对词表，并在英文里用 `[[ ]]` 标出每处出现
- **服务端回校**：按词形变形（复数 / 过去式 / -ing / -ed / -ly）在成文里逐词比对
- **分级重试**：
  - 漏词 > 3 个 → 整篇重写并点名漏掉的词
  - 漏词 ≤ 3 个 → **确定性补写**：让模型写 1~2 句贴合原文的收尾句，服务端拼进正文，必然生效
  - 最多 5 轮，取覆盖最好的一版；词越多温度调得越低（0.8 → 0.4），让模型更"听话"
- **结果明示**：页面写明「全部 N 个词都出现了」，万一漏了会列出具体是哪些

实测：10 词一轮命中；29 词一轮命中；50 词约 1~2 分钟、两轮达到 50/50。

## 双语高亮

- 英文 token：淡黄底 + 加粗；中文 token：淡蓝底 + 加粗；点中后变成实色
- 两侧共用同一个 key，点击可互相点亮；所在整段也会一起提亮
- 若模型的译文里没用词条的说法（用了近义词），该处中文可能不被点亮——英文侧不受影响
